mapUserInfo construit le rôle, l'org et les permissions depuis user_metadata, que l'utilisateur peut modifier lui-même avec supabase.auth.updateUser({ data }). Tant que authAccess s'appuie là-dessus, un compte authentifié peut se donner un rôle ou une org. Ça ne bloque pas l'étape Bearer, mais à traiter avant la mise en production : soit tu déplaces ces données dans app_metadata (écriture réservée au service role), soit tu les lis dans UserOrganization, qui est déjà ta source de vérité. Le LRU de 10 minutes devra alors être invalidé au changement d'appartenance
